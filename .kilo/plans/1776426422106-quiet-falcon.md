# Full Platform Functional Completion Plan (MVP+)

## Overview
This plan outlines the steps required to transition the Afri Connect MVP into a fully functional, multi-role platform. It ensures every user role has a dedicated, working portal, all dead links are connected to functional pages/overlays, the AI scoring engine is interactive, and administrative oversight is tied to real database logs. 

**Design Constraint:** All new UIs and components must strictly adhere to the established "Sage & Slate" institutional design system (soft shadows, `bg-slate-50` / `bg-surface`, rounded `[24px]` corners, and Zambian Kwacha standard).

---

## Sprint 1: Role Dashboard Parity & Design Audit
**Goal:** Ensure all user roles have distinct, fully functional portals without 404 redirects, maintaining strict design consistency.

*   **1.1 Technical Partner Portal (`/dashboard/technical`)**
    *   Create a dedicated dashboard UI tailored to EPC/Engineering metrics (MW capacity delivered, service categories, safety record).
    *   Implement "Marketplace" and "Portfolio" tabs specific to technical engagements (construction, O&M).
*   **1.2 Grant Provider Consolidation**
    *   Merge the `GRANT_PROVIDER` role into the `CAPITAL_PARTNER` role to simplify the ecosystem as discussed.
    *   Update `CapitalStructureType` preferences in the Capital Partner profile to include "Grants/Non-Dilutive".
*   **1.3 Capital Partner Refinement (`/dashboard/investor`)**
    *   Build out functional pages for currently dead links: `Marketplace` (all verified projects), `Portfolio` (active engagements), `Messages`, and `Reports`.
    *   Add functional mock data generation for the "Reports" view.
*   **1.4 Developer Matchmaking (Technical)**
    *   Build the "Find Technical Partners" view for developers, implementing the matching algorithm for EPCs (Service Category + Sector + MW Size).

---

## Sprint 2: Interactive Data Room & Scoring Console
**Goal:** Empower developers and admins to manage documents dynamically, trigger AI, and manually override scores.

*   **2.1 Dynamic Secure Data Room**
    *   Implement file upload functionality directly in the Project Details page (`/projects/[id]`).
    *   Add secure file deletion capabilities with confirmation modals.
    *   Restrict document access based on Engagement state (e.g., NDA signed).
*   **2.2 Interactive AI Scorer**
    *   Create a manual "Re-run AI Analysis" button in the Data Room to conserve API credits.
    *   Implement a loading state and progress indicator while the Gemini function runs.
    *   Ensure the 40/35/25 radar chart updates reactively when a new score is generated.
*   **2.3 Manual Scoring Override**
    *   Build an interface for Developers (to self-report missing metrics) and Admins (for final validation) to manually edit the 21-parameter scores.
    *   Fallback mechanism: Allow manual scoring if the AI fails to parse a complex document.

---

## Sprint 3: Deep Analytics & Admin Command Center
**Goal:** Make analytics actionable and wire up the Admin console to real validation workflows and database logs.

*   **3.1 Developer Project Analytics (`/projects/[id]/analytics`)**
    *   Create a detailed analytics page/overlay.
    *   Track and visualize data for: Profile Views, Funnel Metrics (Intro -> NDA -> DD), and Time in Data Room.
*   **3.2 Admin Verification & Moderation Queue**
    *   Build a split-screen/side-panel UI for Admins to quickly review new Organizations and toggle `verification_status`.
    *   Build the split-screen UI for Admins to review submitted projects (documents on one side, data on the other) and transition them from `submitted` to `validated`, triggering the matching engine.
*   **3.3 Real-time Admin Activity Log**
    *   Refactor the `AdminDashboardPage` to replace the hardcoded "Recent System Activity" with live data from the `audit_logs` table.
    *   Ensure all user actions (login, document upload, status change, scoring run) create an `audit_log` entry.

---

## Sprint 4: End-to-End Navigation, Linking, & Polish
**Goal:** Eliminate all "dead ends" and ensure the platform feels alive with realistic data.

*   **4.1 Global Link Audit**
    *   Scan all components (Sidebars, Headers, Buttons) and wire them to their respective pages, external links, or functional modals.
*   **4.2 Empty States**
    *   Add intelligent, beautifully designed "Empty States" with clear Call-to-Actions for empty portfolios, messages, or marketplaces.
*   **4.3 Realistic Mock Data Seeding**
    *   Seed the database with comprehensive, realistic test data showcasing a broader Sub-Saharan African context (e.g., Solar in Kenya, Hydro in Zambia, Wind in Nigeria).
    *   Ensure this data spans across all roles to allow thorough end-to-end testing of matching and engagements without relying solely on the MVP's strict ZMW focus for test records.
