# Implementation Plan - Matching Engine & PRD Updates

This plan outlines the steps to implement the new matching engine logic and PRD updates for the Energy Capital Match platform.

## 1. Database Schema Updates (Supabase)

### 1.1. Alter Tables
- **`companies`**: Add `is_new_company_with_experienced_team` (BOOLEAN) and `management_team_experience` (JSONB).
- **`capital_partners`**: Add `preferred_project_stage` (project_stage[]), `expected_return_profile` (TEXT), and `preferred_capital_structure` (capital_structure_type[]).
- **`technical_partners`**: Add `payment_terms` (TEXT), `project_type_experience` (TEXT[]), `min_ticket_size_zmw` (BIGINT), `max_ticket_size_zmw` (BIGINT), `years_of_experience` (INTEGER), `company_experience_doc_url` (TEXT).
- **`technical_match_results`**: Add `status` (enum: 'active', 'inactive').

### 1.2. RLS & Permissions
- Update RLS for `project_scores` to restrict `SELECT` access for users with `TECHNICAL_PARTNER` role.

## 2. Type Definitions Update (`web/src/types/index.ts`)
- Update `CapitalPartner`, `TechnicalPartner`, and `Company` interfaces to include the new fields.

## 3. Matching Engine Logic (`web/src/lib/scoring.ts`)

### 3.1. Capital Matching Update
- Extend `calculateCapitalMatchScore` to include:
    - `preferred_project_stage` alignment.
    - `preferred_capital_structure` alignment.
    - **Joint Entity Bonus**: Add +10 points if the project has an accepted EPC engagement.

### 3.2. EPC/Technical Matching Implementation
- Implement `calculateTechnicalMatchScore` using the new 5-criteria formula:
    - **Sector/Technology (25%)**: 100 for exact, 50 for adjacent, 0 otherwise.
    - **Project Size MW (25%)**: 100 if within range, 50 if within 20% of boundary.
    - **Ticket Size (20%)**: 100 if within range, 50 if within 20% of boundary.
    - **Geography (15%)**: 100 if same province, 50 if same country.
    - **Experience (15%)**: Linear scale (0-10 years).
- **Management Team Logic**:
    - Add +10 bonus if `is_new_company_with_experienced_team` is true.
    - Apply -15 penalty if company < 2 years old AND management experience is low/unspecified.

## 4. Service Layer Updates (`web/src/services/projects.ts` & `api.ts`)
- Update `runMatchingEngine` to handle eligibility (validated/verified status).
- Pass engagement data to the matching engine to check for accepted EPCs.
- Implement triggers for recalculation:
    - When an EPC profile is updated.
    - When an EPC match is accepted by a Developer.

## 5. UI & UX Updates

### 5.1. Onboarding & Profile Management
- Update `web/src/app/onboarding/page.tsx` with new fields.
- Implement "Edit Profile" functionality for Capital and Technical partners in their respective dashboards (mimicking the Developer profile edit).

### 5.2. Dashboard Visuals
- **Developer Dashboard**: Update to display Capital and Technical matches in separate lists.
- **Investor Dashboard**: Update `OpportunityCard` to display "Builder Partner: [EPC Name]" if an EPC match is accepted.
- **Technical Dashboard**: Add profile editing and ensure "Experienced Leadership" badge is visible if applicable.

## 6. Verification & Testing
- Unit tests for the new matching formulas in `scoring.ts`.
- End-to-end test of the matching trigger workflow (Profile Update -> Recalculation).
- Verify RLS policies correctly block Technical Partners from seeing project scores.
