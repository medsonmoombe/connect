# Comprehensive Platform Refinement Plan

## Overview
This plan details a systematic approach to refining the Afri Connect platform across Developer, Investor, and Admin profiles. The focus is on fixing dead buttons, repairing file downloads, tailoring UI language to specific user roles, and creating a cohesive, functional experience while maintaining the "Sage & Slate" design system. Existing core features (e.g., AI document scoring) must remain untouched.

---

## Phase 1: Data Room Functionality (File Downloads)
**Goal:** Ensure documents uploaded to the Virtual Data Room (VDR) can be successfully downloaded or viewed.
*   **Task 1.1: Fix Individual Downloads.** Update the `DocumentItem` component in `web/src/app/projects/[id]/page.tsx` to handle file downloads. Add an `onClick` event that uses `window.open(file_url, '_blank')` or creates a temporary anchor tag (`<a>`) with the `download` attribute.
*   **Task 1.2: Implement "Download All".** Wire up the "Download All" button in the Data Room. Given MVP constraints, this should either trigger sequential downloads of the available documents or provide a clear, styled alert advising the user to download files individually if batch downloading isn't supported by the storage setup.

---

## Phase 2: Role-Specific UI & Language Differentiation
**Goal:** Prevent Developer and Investor profiles from sharing the exact same terminology in the Data Room and Analytics views.
*   **Task 2.1: Contextual Data Room Headers.** In `web/src/app/projects/[id]/page.tsx`, dynamically change the header "Secure Data Room". For Developers (`isOwner`), it should say "Manage Data Room". For Investors (`isPartner`), it should say "Due Diligence Room".
*   **Task 2.2: Contextual Analytics Block.** The "Market Interest" sidebar block (showing Views, NDA Requests) is developer-centric. Hide this block for Investors (`!isOwner && isPartner`). Optionally, replace it with a "Due Diligence Progress" block for the investor.
*   **Task 2.3: Active Discussions Filtering.** The "Active Discussions" block currently shows hardcoded threads (e.g., GreenGrowth Capital). Refactor this to be role-aware: Investors should only see their specific thread/engagement with the developer, whereas developers see all active partner threads.
*   **Task 2.4: Header Actions.** The "Share" and "Request Review" buttons in the project header are currently dead. Hide them entirely for Investors. For Developers, implement a simple "Copy to Clipboard" action for the Share button.

---

## Phase 3: Developer Dashboard Navigation & Actions
**Goal:** Eliminate dead ends within the Developer portal (`web/src/app/dashboard/developer/page.tsx`).
*   **Task 3.1: Data Room Tab Navigation.** The "Upload Document" button on the static Data Room tab is dead. Modify this to navigate the user to their primary project's Data Room (`/projects/${projects[0]?.id}`) or display an "Empty State" prompting them to select a project first.
*   **Task 3.2: Analytics Export.** Add a functional `onClick={() => window.print()}` handler to the "Export Portfolio Report" button in the Analytics tab, matching the behavior of the main dashboard.
*   **Task 3.3: Partner Engagement.** In the "Find Partners" tab, wire the "Request Proposal" button on the technical partner cards. It should either create a new Engagement record (`INTRO_SENT`) or trigger a success toast/alert indicating the request was simulated.
*   **Task 3.4: Inbox Link.** Remove or fix the dead "View Milestone Room" text link in the header of the Messages tab.

---

## Phase 4: Investor Dashboard Navigation & Actions
**Goal:** Eliminate dead ends within the Investor portal (`web/src/app/dashboard/investor/page.tsx`).
*   **Task 4.1: Marketplace Empty State.** Wire the "Clear Filters" button in the marketplace empty state to reset the view or call `window.location.reload()`.
*   **Task 4.2: Bookmarking.** The bookmark icon on the `OpportunityCard` does nothing. Add a local `isBookmarked` state to toggle the icon's fill color and display a quick toast notification ("Project saved to watchlist").

---

## Phase 5: Admin Dashboard Polish
**Goal:** Ensure the command center has no broken flows.
*   **Task 5.1: System Console Link.** Wire the large "SYSTEM CONSOLE" button at the bottom of the System Health card in `web/src/app/dashboard/admin/page.tsx` to link to `/dashboard/admin/settings` or `/dashboard/admin/verification`.

---

## Execution Constraints
1.  **Read/Score Integrity:** Under no circumstances should modifications to `web/src/app/projects/[id]/page.tsx` disrupt the `runAIAnalysis` function or the `handleFileUpload` logic.
2.  **Design System Compliance:** All newly added UI states (like toasts or empty states) must strictly utilize "Sage & Slate" principles: `bg-slate-50`, `bg-white`, soft shadows (`shadow-soft` or `shadow-xl`), `rounded-[24px]` to `rounded-[40px]`, and `Inter` typography.
3.  **Iterative Approach:** Tackle each Phase sequentially. Verify the specific component's functionality locally before moving to the next profile.
